
# ChaCha20 C语言实现分析

## 1. 总结
这是一个符合 RFC 7539 标准的 ChaCha20 流密码算法的 C 语言实现。
- **核心功能**: 提供流加密/解密功能（对称算法，加密解密互逆）。
- **标准兼容**: 采用 256 位密钥 (32 字节)、96 位 Nonce (12 字节) 和 32 位初始计数器，符合 IETF RFC 7539 的现代标准。
- **设计目标**: 高性能、高安全性且易于软件实现，不依赖硬件加速。

## 2. 特点与特征

### ARX 结构设计
- 核心算法基于 **Add-Rotate-Xor (ARX)** 操作：
    - 32 位整数加法 (Addition)
    - 循环左移 (Rotation)
    - 异或 (Xor)
- **优势**: 这些操作在所有现代 CPU 上都能单周期执行，使得 ChaCha20 非常快，且天然抵抗计时攻击（Constant-time），因为这些指令的执行时间与数据无关。

### 状态矩阵与 Quarter Round
- **状态**: 内部维护一个 4x4 的 32 位整数矩阵（512 位状态）。
    - 常量: 4 个字 ("expand 32-byte k")
    - 密钥: 8 个字 (256 位)
    - 计数器: 1 个字 (32 位)
    - Nonce: 3 个字 (96 位)
- **混合**: 通过 `QR` (Quarter Round) 宏对状态矩阵的列和对角线进行 20 轮（10 次双轮）混合，确保充分的扩散性。

### 流密码特性
- **密钥流生成**: 算法生成一个伪随机密钥流 (Key Stream)。
- **异或加密**: `chacha20_crypt` 函数将生成的密钥流与明文进行逐字节异或 (`input[i] ^ block[i]`) 得到密文。由于异或的性质，再次异或即可解密。
- **随机访问**: 通过设置初始计数器，可以从流的任意位置开始加密/解密，支持并行处理。

## 3. 魔改建议

### 轮数调整 (ChaCha8 / ChaCha12)
标准的 ChaCha20 使用 20 轮。
- **魔改点**: 修改 `chacha20_block` 中的循环次数。
    - 改为 `i < 4` 即为 ChaCha8 (8 轮)。
    - 改为 `i < 6` 即为 ChaCha12 (12 轮)。
- **效果**: 显著提升速度（ChaCha8 极快），但安全性会有所降低（尽管 ChaCha8 目前仍被认为是安全的）。Google 在早期移动端 TLS 中曾使用 ChaCha8/12。

### 扩展 Nonce (XChaCha20)
RFC 7539 使用 96 位 Nonce，这对于随机生成 Nonce 来说碰撞概率略高（虽仍很低）。
- **魔改点**: 引入 HChaCha20 算法，支持 192 位 (24 字节) 的扩展 Nonce。
- **效果**: 允许安全地使用随机生成的 Nonce，无需维护计数器状态，非常适合无状态协议。

### 自定义常量
算法使用了 ASCII 字符串 "expand 32-byte k" 作为初始常量。
- **魔改点**: 修改 `constant` 数组的内容。
- **效果**: 改变了初始状态，生成的密钥流将完全不同，可用于构建私有协议或增加混淆。

### 64 位计数器
当前实现遵循 RFC 7539 使用 32 位计数器 + 96 位 Nonce。原始的 Bernstein 规范使用 64 位计数器 + 64 位 Nonce。
- **魔改点**: 修改 `chacha20_init` 和 `chacha20_block` 中填充矩阵的方式，将矩阵第 13 个字也用作计数器的高 32 位。
- **效果**: 支持更长的单次加密流（2^64 个块 vs 2^32 个块），适用于超大数据传输。
