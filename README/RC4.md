
# RC4 C语言实现分析

## 1. 总结
这是一个极简的 RC4 (Rivest Cipher 4) 流密码算法的 C 语言实现。
- **核心功能**: 实现了 RC4 算法的完整流程，包括 KSA (Key-scheduling algorithm) 和 PRGA (Pseudo-random generation algorithm)。
- **使用方式**: 提供了一个单一的接口 `rc4_encrypt`，由于 RC4 是对称流密码，该函数同时用于加密和解密。
- **状态管理**: 使用了一个**全局**静态数组 `S[256]` 来存储 S-Box 状态。这意味着该实现**不是线程安全的**，且不支持同时处理多个加密流。

## 2. 特点与特征

### 极其简洁的实现
- **代码量**: 整个实现不到 50 行代码，非常紧凑。
- **无依赖**: 不依赖任何外部库（除了 `RC4.h` 声明），完全自包含。

### 算法流程
1.  **KSA (初始化)**:
    - `init_sbox` 函数首先将 S-Box 初始化为 `0..255` 的线性序列。
    - 创建一个临时数组 `T`，根据密钥重复填充。
    - 使用密钥 `T` 对 `S` 进行置换打乱，确保初始状态与密钥高度相关。
2.  **PRGA (生成与加密)**:
    - 在 `rc4_encrypt` 的主循环中，通过 `i` 和 `j` 指针不断更新 S-Box 的状态。
    - 每次循环生成一个伪随机字节 `k`。
    - 将 `k` 与明文数据进行异或 (`^`) 操作得到密文。

### 全局状态 (潜在风险)
- 代码使用了 `static unsigned char S[256];`。
- **优点**: 减少了栈空间的使用，函数调用参数更少。
- **缺点**: **严重限制**。无法在多线程环境下使用，也无法在单线程中交替处理两个不同的数据流。每次调用 `rc4_encrypt` 都会重置 S-Box，这意味着它不支持流式处理（即不能先加密一部分数据，再接着加密下一部分），必须一次性加密所有数据。

## 3. 魔改建议

### 去除全局状态 (Context化)
当前的全局 `S` 数组是最大的限制。
- **魔改点**: 定义一个 `rc4_context` 结构体，包含 `S[256]`, `i`, `j`。
- **效果**: 支持多线程并发，支持流式分块加密（`rc4_init`, `rc4_update`）。

### 丢弃前 N 字节 (RC4-drop)
RC4 的初始几个字节被证明存在偏差（不够随机），容易遭受攻击（如 WEP 破解）。
- **魔改点**: 在 `init_sbox` 完成后，预先运行 PRGA 循环 768 或 1024 次，丢弃生成的输出。
- **效果**: 显著提高安全性，演变为 **RC4-drop** 算法。

### 增强的密钥调度 (Spritz)
RC4 的 KSA 过于简单。
- **魔改点**: 实现 **Spritz** 算法（RC4 的改进版）。它使用了更复杂的更新函数（类似海绵结构）。
- **效果**: 提供更好的统计特性和抗攻击能力。

### 性能优化
- **魔改点**: 将 `i`, `j` 等变量定义为 `register` 或 `uint8_t` 以提示编译器优化。虽然现在的编译器已经很聪明，但在某些嵌入式平台上仍有帮助。
- **魔改点**: 循环展开 PRGA 循环，一次生成 4 或 8 个字节。
