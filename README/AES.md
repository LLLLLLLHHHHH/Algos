
# AES C语言实现分析

## 1. 总结
这是一个紧凑且可移植的 AES (Advanced Encryption Standard) 算法的 C 语言实现。
- **支持标准**: 完整支持 AES-128, AES-192, 和 AES-256 标准（通过宏定义配置）。
- **工作模式**: 实现了三种常用的工作模式：ECB (电子密码本), CBC (密码分组链接), 和 CTR (计数器模式)。
- **依赖**: 仅依赖标准 C 库 (`stdint.h`, `string.h`)，易于移植到嵌入式系统或其他平台。
- **结构**: 代码结构清晰，将核心算法（轮函数）与工作模式解耦。

## 2. 特点与特征

### 灵活的配置
- 通过 `AES.h` 中的宏定义 (`AES128`, `AES192`, `AES256`) 来选择密钥长度。
- 默认配置为 AES-128。
- 自动根据选定的密钥长度计算密钥扩展所需的内存大小 (`AES_keyExpSize`)。

### 面向对象风格的上下文管理
- 定义了 `AES_ctx` 结构体来保存状态：
    - `RoundKey`: 扩展后的轮密钥。
    - `Iv`: 初始化向量 (Initialization Vector)。
- 这种设计使得代码是线程安全的（只要不同线程操作不同的 `ctx`），并且支持同时处理多个加密流。

### 核心算法实现
- **查表法**: 使用预计算的 `sbox` (S盒) 和 `rsbox` (逆S盒) 进行字节代换，平衡了代码体积和速度。
- **有限域运算**: 实现了 `xtime` (x2) 和 `Multiply` 函数来处理 GF(2^8) 域上的乘法，用于 `MixColumns` 操作。
- **密钥扩展**: `KeyExpansion` 函数负责将初始密钥扩展为每一轮所需的轮密钥，支持 `Rcon` 轮常量处理。

### 支持的工作模式
1.  **ECB**: 最基础的模式，将数据分成块独立加密。**注意**: 不安全，不建议用于大于一个块的数据。
2.  **CBC**: 引入了 IV，前一个密文块与当前明文块异或。**注意**: 需要处理填充（Padding），且不能并行加密。
3.  **CTR**: 将 AES 变为流密码，通过加密计数器产生密钥流与明文异或。**特征**: 加解密使用同一个函数 (`AES_CTR_xcrypt_buffer`)，支持随机访问，可并行处理。

## 3. 魔改建议

### 性能魔改：T-Table 优化
当前的实现是基于字节操作（byte-oriented）的。
- **魔改方向**: 可以将 `SubBytes`, `ShiftRows`, 和 `MixColumns` 三步合并为查表操作（T-Tables）。
- **效果**: 将操作转换为 32 位 XOR 运算，显著提高速度，但会增加 4KB-8KB 的代码/数据体积（适用于内存充足的场景）。

### 安全魔改：抗侧信道攻击 (Constant-Time)
当前的查表法实现容易受到缓存计时攻击 (Cache-timing attacks)，因为查表的时间可能取决于索引（即密钥/数据）。
- **魔改方向**: 使用**比特切片 (Bitslicing)** 技术重新实现 S-Box，或者使用逻辑运算组合模拟 S-Box，完全避免查表。
- **效果**: 实现常数时间执行，增强对侧信道攻击的防御能力，但会大幅降低性能并增加代码复杂度。

### 算法定制：私有变体
如果需要一个非标准的、私有的加密算法（用于混淆或特定需求）：
- **魔改 S-Box**: 生成一个新的 256 字节置换表及其逆表来替换标准的 `sbox`/`rsbox`。
- **修改多项式**: 修改 `MixColumns` 中使用的乘法系数（目前是 0x02, 0x03, 0x01, 0x01）。
- **修改轮数**: 调整 `Nr` 的值，减少轮数以提高速度（降低安全性），或增加轮数以提高安全性。

### 功能扩展：GCM 模式
当前只支持 ECB, CBC, CTR。
- **魔改方向**: 基于 CTR 模式，增加 GMAC (Galois Message Authentication Code) 部分，实现 **GCM (Galois/Counter Mode)**。
- **效果**: 提供认证加密 (Authenticated Encryption)，即同时保证数据的保密性和完整性，这是现代 TLS 等协议的首选模式。
