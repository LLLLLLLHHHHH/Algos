
# MD5 C语言实现分析

## 1. 总结
这是一个经典且紧凑的 MD5 (Message-Digest Algorithm 5) 哈希算法的 C 语言实现。
- **核心功能**: 将任意长度的输入数据（字节流）计算为一个 128 位 (16 字节) 的哈希值（指纹）。
- **标准兼容**: 符合 RFC 1321 标准规范。
- **设计风格**: 代码结构清晰，使用了大量的内联函数 (`inline`) 和宏定义来优化位运算性能。

## 2. 特点与特征

### 四轮变换结构
- **核心算法**: `transform` 函数实现了 MD5 的核心压缩函数，处理 512 位 (64 字节) 的数据块。
- **四种非线性函数**: 定义了 `F`, `G`, `H`, `I` 四个基本的位运算函数，分别对应 MD5 的四轮操作。
- **64 步迭代**: 每一轮包含 16 步操作（`FF`, `GG`, `HH`, `II`），总共 64 步。每一步都包含非线性函数运算、模加、循环左移 (`ROTATE_LEFT`) 和常量加法。

### 上下文管理
- **状态维护**: 使用 `ctx` 结构体维护哈希计算的中间状态：
    - `count[2]`: 记录已处理的数据总位数（64 位计数器，低位在前）。
    - `state[4]`: 4 个 32 位整数（A, B, C, D），初始化为特定的魔数，最终存储哈希结果。
    - `buffer[64]`: 64 字节的缓冲区，用于累积不足一个块的数据。
- **分块处理**: `md5Update` 函数负责将输入数据分块（每块 64 字节），并调用 `transform` 进行处理，同时处理跨块的数据拼接。

### 填充与收尾
- **MD5 填充**: `md5Finish` 函数实现了标准的 MD5 填充逻辑：
    1.  追加一个 `1` 位 (0x80)。
    2.  追加若干 `0` 位，直到长度满足 `(length + 8) % 64 == 0`。
    3.  追加原始数据长度（64 位，小端序）。
- **小端序处理**: 代码中显式实现了 `uIntArrayToBytes` 和 `bytesToUIntArray` 函数，确保在不同字节序的机器上都能正确处理 32 位整数与字节流的转换（MD5 算法要求小端序）。

## 3. 魔改建议

### 性能优化：循环展开
当前的 `transform` 函数已经手动展开了 64 步操作，这是为了避免循环带来的分支预测开销。
- **魔改点**: 进一步针对特定架构（如 x86 AVX2 或 ARM NEON）使用 SIMD 指令集并行处理多个数据块（如果需要同时计算多个文件的哈希）。

### 算法定制：修改常量与初值
MD5 的安全性依赖于其特定的常量和初值。
- **魔改点**:
    - 修改 `md5Init` 中的初始状态 (`state`) 魔数。
    - 修改 `transform` 函数中 64 步操作所使用的正弦常量表（即那些 `0xd76aa478` 等十六进制数）。
    - 修改循环左移的位数 (`s` 参数)。
- **效果**: 创造一个全新的、私有的哈希算法。虽然不能增加抗碰撞性，但可以用于私有协议的完整性校验，防止攻击者直接使用标准 MD5 工具伪造数据。

### 功能扩展：HMAC-MD5
当前只实现了基础的 MD5。
- **魔改点**: 基于此实现封装 **HMAC (Hash-based Message Authentication Code)** 结构。
    - `HMAC(K, m) = H((K' ^ opad) || H((K' ^ ipad) || m))`
- **效果**: 提供带密钥的消息认证功能，常用于身份验证和数据完整性保护。

### 碰撞攻击测试
MD5 已被证明是不安全的（存在快速碰撞攻击）。
- **魔改点**: 作为教学或研究，可以尝试植入“后门”或特定的碰撞模式，或者实现“前缀碰撞”生成器，展示 MD5 的脆弱性。**注意：仅限研究用途。**
