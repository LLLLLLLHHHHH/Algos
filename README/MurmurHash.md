
# MurmurHash3 (32-bit) C语言实现分析

## 1. 总结
这是一个 **MurmurHash3 (32-bit)** 算法的简洁 C 语言实现。
- **算法版本**: 实现了 MurmurHash 系列中应用最广泛的第 3 版 (MurmurHash3) 的 32 位版本。
- **核心功能**: 将任意长度的输入数据（Key）映射为一个 32 位无符号整数（Hash Value）。
- **适用场景**: 适用于哈希表查找、布隆过滤器、数据校验等非加密场景。

## 2. 特点与特征

### 高性能与雪崩效应
- **非加密哈希**: MurmurHash 专为速度和哈希分布质量而设计，不追求抗原像攻击等加密安全性，因此速度极快。
- **雪崩效应 (Avalanche Effect)**: 输入数据的微小变化（如改变 1 个 bit）会引起哈希值的巨大变化。通过多次乘法 (`c1`, `c2`)、移位 (`ROTL`) 和异或操作，确保了极佳的混合效果。

### 算法结构
1.  **分块处理 (Body)**:
    - 将输入数据按 4 字节（32 位）一组进行处理。
    - 每个块都经过一系列的乘法 (`k * c1`, `k * c2`) 和循环左移 (`ROTL`) 操作，然后与当前哈希值 `h` 进行异或混合。
2.  **尾部处理 (Tail)**:
    - 使用 `switch-case` 巧妙处理最后不足 4 字节的剩余数据（1, 2 或 3 字节），确保所有输入数据都被利用。
3.  **最终混合 (Finalization)**:
    - 将数据长度混入哈希值，防止不同长度但前缀相同的数据产生碰撞。
    - 通过多次位移和乘法 (`fmix32` 逻辑)，进一步打乱二进制位，确保高位和低位的分布均匀。

### 字节序无关性
- 代码中包含 `htole32` (Host to Little Endian) 逻辑，确保在大端序机器上也能产生与小端序机器一致的哈希值（MurmurHash 标准定义为小端序处理）。

## 3. 魔改建议

### 64 位 / 128 位扩展
当前实现仅输出 32 位哈希值。
- **魔改点**: 实现 **MurmurHash3_x86_128** 或 **MurmurHash3_x64_128**。
- **效果**: 提供 128 位哈希值，碰撞概率极低，适用于大规模分布式系统（如 Cassandra, Hadoop 等）。

### 种子 (Seed) 定制
`murmurhash` 函数接受一个 `seed` 参数。
- **魔改点**: 在应用层固定一个非零的私有 Seed，或者基于时间/用户 ID 动态生成 Seed。
- **效果**: 可以作为一种简单的非加密“带密钥哈希”，防止针对特定哈希表的 HashDoS 攻击（虽然 SipHash 更适合此目的）。

### 增量式哈希 (Streaming)
当前实现要求一次性传入所有数据。
- **魔改点**: 重构为 `Init`, `Update`, `Final` 形式的 API。
- **效果**: 支持处理流式数据或无法一次性加载到内存的大文件。

### 硬件加速
虽然 MurmurHash 已经很快，但可以进一步优化。
- **魔改点**: 使用 SIMD 指令集（如 AVX2）并行处理多个数据块。
- **注意**: 由于 MurmurHash 的每一步都依赖上一步的结果（串行依赖），单流的 SIMD 优化较难，但可以对多流（同时计算多个 Key）进行 SIMD 优化。
