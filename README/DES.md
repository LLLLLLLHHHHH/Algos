# DES Algorithm Implementation Analysis

## 1. 总结 (Summary)
**DES (Data Encryption Standard)** 是一种经典的对称密钥分组密码算法，由 IBM 在 1970 年代初期开发，并于 1977 年被美国国家标准局 (NBS, 现 NIST) 采纳为联邦信息处理标准 (FIPS 46)。
尽管 DES 由于其 56 位的短密钥长度在现代计算能力下已被认为不再安全（易受暴力破解攻击），但它在密码学历史上具有里程碑意义，并且是理解现代分组密码（如 AES）设计思想的基础。

## 2. 特点与特征 (Features & Characteristics)

### 2.1 基础参数
*   **分组长度**：64 位 (8 字节)。
*   **密钥长度**：64 位 (其中 8 位用于奇偶校验，实际有效密钥长度为 56 位)。
*   **结构**：Feistel 网络结构。
*   **轮数**：16 轮。

### 2.2 核心机制
*   **Feistel 结构**：加密和解密过程高度对称，解密仅需将子密钥的使用顺序倒置。
*   **S-盒 (Substitution Boxes)**：DES 的核心非线性部件。8 个 S-盒将 48 位输入压缩为 32 位输出，提供了算法的混淆 (Confusion) 特性。
*   **置换 (Permutation)**：包括初始置换 (IP)、逆初始置换 (IP⁻¹)、扩展置换 (E) 和 P-置换 (P)。这些线性变换提供了算法的扩散 (Diffusion) 特性。

### 2.3 支持的模式 (Modes of Operation)
本项目实现了 DES 的五种标准工作模式：
*   **ECB (Electronic Codebook)**：最简单的模式，各块独立加密。不推荐用于长报文。
*   **CBC (Cipher Block Chaining)**：引入初始化向量 (IV)，各块之间通过异或链接，安全性高于 ECB。
*   **CFB (Cipher Feedback)**：将分组密码转换为流密码，支持反馈。
*   **OFB (Output Feedback)**：将分组密码作为同步流密码生成密钥流，无错误传播。
*   **CTR (Counter)**：计数器模式，并行性好，随机访问能力强。

## 3. 安全性分析
*   **暴力破解**：由于有效密钥只有 56 位，密钥空间约为 $7.2 \times 10^{16}$。现代硬件（如 FPGA 或 GPU 集群）可以在几小时甚至几分钟内遍历整个密钥空间。
*   **差分分析与线性分析**：DES 对差分分析有较强的抵抗力（设计者已知该攻击方法），但对线性分析相对较弱。
*   **现状**：DES 已被 **AES** 取代，不再建议在新系统中使用。为了兼容旧系统，有时会使用 **3DES (Triple DES)**，即对数据进行三次 DES 运算，但这也会降低性能。

## 4. 实现细节
*   **纯 C 实现**：代码仅依赖标准库，易于移植。
*   **位操作优化**：核心算法使用 `uint64_t` 进行位级置换和操作，模拟硬件行为。
*   **API 设计**：
    *   `DES_init` / `DES_init_iv`：初始化上下文和密钥调度。
    *   `DES_xxx_encrypt` / `DES_xxx_decrypt`：各模式的加密/解密接口。

## 5. 魔改建议 (Modification)
*   **增加轮数**：将 16 轮增加到 32 轮或更多，可以增加线性分析的难度，但无法解决密钥过短的问题。
*   **替换 S-盒**：可以使用更复杂的 S-盒（如 AES 的 S-盒）来增强非线性度。
*   **密钥扩展**：修改密钥调度算法 (Key Schedule) 以支持更长的密钥（例如 128 位），但这通常意味着设计一个新的算法（类似 Skipjack 或 IDEA）。
