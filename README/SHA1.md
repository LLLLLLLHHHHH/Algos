
# SHA1 C语言实现分析

## 1. 总结
这是一个标准的 SHA1 (Secure Hash Algorithm 1) 哈希算法的 C 语言实现。
- **核心功能**: 将任意长度的输入数据计算为一个 160 位 (20 字节) 的哈希值。
- **标准兼容**: 符合 RFC 3174 标准规范。
- **设计风格**: 代码结构与 MD5 实现非常相似，提供了 Init/Update/Final 形式的 API。

## 2. 特点与特征

### 80 步变换
- **核心算法**: `SHA1Transform` 函数实现了 SHA1 的核心压缩函数，处理 512 位 (64 字节) 的数据块。
- **消息扩展**: 将 16 个 32 位字的消息块扩展为 80 个 32 位字 (`w[80]`)，利用了循环左移操作（这是 SHA1 与 MD5 的主要区别之一，也是 SHA0 到 SHA1 的改进点）。
- **四轮迭代**: 包含 4 轮操作，每轮 20 步，共 80 步。
    - 0-19 步: 使用 `(b & c) | (~b & d)` 和常量 `0x5A827999`
    - 20-39 步: 使用 `b ^ c ^ d` 和常量 `0x6ED9EBA1`
    - 40-59 步: 使用 `(b & c) | (b & d) | (c & d)` 和常量 `0x8F1BBCDC`
    - 60-79 步: 使用 `b ^ c ^ d` 和常量 `0xCA62C1D6`

### 上下文管理
- **状态维护**: 使用 `SHA1_CTX` 结构体：
    - `state[5]`: 5 个 32 位整数（A, B, C, D, E），初始化为特定的常量。
    - `count[2]`: 64 位位计数器。
    - `buffer[64]`: 64 字节缓冲区，用于分块处理。
- **大端序处理**: SHA1 算法要求使用大端序 (Big-Endian) 处理 32 位整数。代码中显式实现了 `get_uint32_be` 和 `put_uint32_be` 函数，确保在小端序机器（如 x86）上也能正确运行。

## 3. 魔改建议

### 性能优化：SIMD
SHA1 的消息扩展过程具有一定的数据依赖性，但核心压缩函数可以通过 SIMD 指令集（如 Intel SHA Extensions 或 ARMv8 Cryptography Extensions）进行大幅加速。
- **魔改点**: 检测 CPU特性，如果支持硬件 SHA1 指令，直接调用硬件指令替代软件实现。

### 安全性增强：SHA-2 升级
SHA1 已经被攻破（SHAttered 攻击），不再被认为是安全的。
- **魔改点**: 将代码升级为 **SHA-256**。
    - 增加状态变量从 5 个到 8 个。
    - 修改消息扩展逻辑和压缩函数逻辑。
    - 修改常量表。
- **效果**: 提供真正的密码学安全性，符合现代标准。

### HMAC-SHA1
虽然 SHA1 的抗碰撞性已破，但 HMAC-SHA1 的安全性目前仍被认为是可接受的（用于 HMAC 时主要依赖抗原像性）。
- **魔改点**: 封装实现 `HMAC(K, m) = SHA1((K' ^ opad) || SHA1((K' ^ ipad) || m))`。
- **效果**: 支持 HOTP (基于 HMAC 的一次性密码) 等遗留系统。

### 算法定制：Git 风格哈希
Git 使用 SHA1 计算对象的 ID，但在计算前会添加一个头部（如 `blob <len>\0`）。
- **魔改点**: 封装一个 `git_hash_object` 函数，自动处理 Git 风格的头部构造和哈希计算。
