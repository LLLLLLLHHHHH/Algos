
# SHA-384 实现分析

## 1. 总结
SHA-384 是 SHA-2 系列中的 384 位输出变体，与 SHA-512 共用同一套 64 位核心，仅初始向量 (IV) 与输出截断不同。
- **核心功能**: 将任意长度输入计算为 384 位 (48 字节) 哈希；C 实现提供 `sha384()` 一步到位及 `sha384_init` / `sha512_hash` / `sha512_done` 流式接口（与 SHA512 共用上下文）。
- **标准兼容**: 符合 FIPS 180-4。
- **实现方式**: C 与 SHA-512 共用 `c/SHA512` 核心（不同 IV，结果取前 48 字节）；JS 使用 Node `crypto.createHash('sha384')` 或 Web Crypto `SHA-384`。

## 2. 特点与特征

### 与 SHA-512 的关系
- **同一核心**: 块大小 1024 位 (128 字节)，80 轮 64 位运算，K 表与 SHA-512 相同。
- **不同 IV**: SHA-384 使用 FIPS 180-4 规定的另一组 8 个 64 位初值（前 8 个素数立方根小数部分），指纹中常用其低 32 位（如 0xf3bcc908 等）参与 u32 匹配。
- **输出**: 取 SHA-512 输出的前 48 字节。

### 上下文与 API
- C: `sha512_context` 经 `sha384_init()` 初始化后，用 `sha512_hash` / `sha512_done` 计算，输出截断为 48 字节；或直接调用 `sha384(data, len, hash)`。
- JS: `sha384Sync` / `sha384Async`，Node 下同步可用，浏览器下为异步。

## 3. 魔改建议

- **硬件加速**: 若平台提供 SHA-512 扩展指令，可在此处复用同一套加速路径。
- **HMAC-SHA384**: 在现有 HMAC 框架下增加 `hmac_sha384`，用于 TLS、API 签名等场景。
